## 任务（续2）：ofd.js 不可行，改用纯 JS 抽 OFD 文本
- 关键结论：`ofd.js@1.x`（npm 发布版）依赖商用授权内核 `parser_helper_x.js`，解析时**远程校验授权**返回「授权信息错误」，且 0.9.20 免授权构建还需独立 `FreetypeKit.js`（FreeType wasm，公开源取不到）→ 两条路都走不通，不应破解授权。
- 用户澄清：要支持的是 **OFD（国标版式文档 `.ofd`）** 而非 ODF；样本 `虚拟体检报告.ofd`（/Users/viki/Downloads）可用于实测。
- 改用**纯 JS 方案**：`jszip` 解包 OFD(ZIP+XML) + 正则抽每页 `<TextCode>` 文本。免费、零授权、无需渲染内核/字体，纯浏览器端。已 `pnpm add jszip`(^3.10.1)。
- src/App.vue 改动：删除 `ofd.js` 动态 import/script 注入与 `renderOfd` 渲染逻辑；`extractOfdText(arrayBuffer)`（定位 OFD.xml→DocRoot→Document.xml，收集页面 BaseLoc，逐页抽 TextCode）；`handleOfd()` 仅抽取文本（无矢量预览）。硬约束不变：仅 `.ofd` 走此分支，其余走 anydoc。引擎标识改 `OFD(纯JS)`。
- 移除 `public/ofd-umd.js`（失效 vendored 文件）；`vite.config.js` 已无 ofd.js 预打包项。
- 真实验证（puppeteer-core + 系统 Chrome 无头）：上传真实 `虚拟体检报告.ofd` → 引擎 `OFD(纯JS)`，解析 **5 页 / 230 段文本 / 2,363 字符**，抽出生效内容（张伟、体检编号 TJ202608140001 等）；同时 my.pdf 仍走 anydoc 正常 → 硬约束成立。`pnpm build` 通过（jszip 进主包 167KB，wasm+pdf 正确打包）。
- 删除了 e2e/verify 脚手架脚本。
- 说明：jszip 为静态 import（常驻主包），但 OFD 解析逻辑 `extractOfdText` 仅 `.ofd` 时执行，非 OFD 文件不触发。
